# Atomic Clock v0.6.1-dev.5

Updater hardening and polish milestone following the successful on-device
dev.3 → dev.4 secure update.

## Fixed

- The updater now enters the visible **Verifying** state after downloads finish,
  so checksum/signature/package validation is no longer hidden behind 100% download.
- Fixed the Android unknown-app-source permission return path. After permission is
  granted, **Continue installation** retries the already-verified installer handoff
  instead of repeatedly reopening Android Settings.
- Failed or rejected staged downloads are deleted immediately.
- Staged files for the newly installed version are removed when the updated app starts.
- Abandoned staging directories expire automatically after 24 hours.
- Offline and timeout failures now produce concise updater-specific messages.

## Changed

- Mandatory manifests are visibly identified as a **required** update in Settings.
  Android's normal user-confirmed package installer remains mandatory; Atomic Clock
  never silently installs an update.
- Existing SHA-256, detached RSA signature, package ID, version, APK signer, approved
  origin, channel, and protocol checks remain unchanged and fail closed.

## Validation target

This build should be tested for:

- current/no-update behavior;
- Development channel discovery;
- interrupted/offline update failure;
- installer permission flow;
- installer cancellation followed by retry;
- normal signed upgrade with settings/widget state preserved;
- staging cleanup after the newer app starts.
