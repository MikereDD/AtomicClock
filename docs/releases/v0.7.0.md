# Atomic Clock v0.7.0

Atomic Clock v0.7.0 introduces the first production-ready Typezer∅ Android
self-updater and completes the release-integrity foundation begun in v0.6.0.

## Secure in-app updates

Atomic Clock can now discover updates from the selected **Stable** or
**Development** channel and hand a verified APK to Android's system package
installer.

Before an APK is accepted, Atomic Clock validates:

- approved HTTPS release origins;
- schema-2 release metadata;
- exact numeric version and channel rules;
- updater-protocol compatibility;
- APK filename, size, and SHA-256;
- detached `.apk.sig` filename, size, and SHA-256;
- RSA/SHA-256 detached release signature;
- pinned Typezer∅ release-key identity;
- Atomic Clock package ID;
- APK version;
- pinned Android APK signing certificate.

The critical trust checks are repeated immediately before installer handoff.
Atomic Clock never silently installs an update.

## Updater reliability

- App-controlled staging directory.
- Visible Downloading and Verifying states.
- Clear offline and timeout failures.
- Android 8+ per-app install-permission flow.
- Installer cancellation and retry support.
- Failed/rejected staging is removed immediately.
- Abandoned staging expires automatically.
- Successful-update staging is cleaned when the new version starts.
- Mandatory manifests are visibly identified as required without bypassing
  Android's installer confirmation.

## Release integrity

Public release bundles now include:

- signed Android APK;
- detached RSA/SHA-256 `.apk.sig`;
- SHA-256 checksums;
- APK signer verification record;
- schema-2 release manifest;
- source repository/tag/commit provenance;
- release notes and changelog.

## Validation

The updater was validated on-device through a normal release-signed
`0.6.1-dev.5` → `0.6.1-dev.6` upgrade, including permission, cancellation/retry,
offline behavior, settings/widget persistence, tampered APK/signature rejection,
unapproved release-key rejection, package/signer mismatch rejection, channel
rejection, and updater-protocol incompatibility rejection.
